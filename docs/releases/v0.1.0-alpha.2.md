# Nomos 0.1.0-alpha.2

Hardening of the masterless Cell and of how it is released. It adds no resource family and no capability: the Cell does what alpha.1 did, with one owner per state directory, a read-only Trace, a package that brings what the Cell runs, and a release process that cannot pass by comparing a commit with itself. It is an alpha. Use it on hosts you can rebuild.

## Install

The package is for Debian 12 and 13 on amd64 with systemd. Download `nomos-cell_0.1.0-alpha.2_amd64.deb`, `SHA256SUMS`, and `RELEASE-EVIDENCE.json` from this release, check the digest, and install:

```sh
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify nomos-cell_0.1.0-alpha.2_amd64.deb --repo kmosoti/Nomos
sudo apt-get install ./nomos-cell_0.1.0-alpha.2_amd64.deb
```

The package now declares `Depends: systemd, dbus, passwd, apt`, so apt brings what the Cell runs.

## What Changed

- **One owner of a state directory.** `enforce` and `import` take an exclusive lock on the state directory and hold it for the whole run. A second process ends with status 1 and `already in use`, having changed nothing. A killed holder gives the lock up with no cleanup. (#30)
- **A read-only Trace.** `trace` and `events` never create, write, truncate, or repair anything in the state directory. A torn journal tail is reported and left in place. (#36)
- **A state directory the Cell can trust.** The state directory, its lock file, the journal, the content store, and every blob read must be the right type, not a link, owned by the user running the Cell, and closed to group and others. Anything else is refused before the journal is replayed. The packaged `/var/lib/nomos` and a `--state` path meet the same rule. (#37)
- **Release gates that fail closed.** A tag is checked against the previous release tag, never against `main`. A base that cannot be resolved, is not a tag, is the tagged commit, or is not its ancestor fails the job. (#31)
- **Evidence tests are protected.** The integration tests of every crate, and the inline tests the semantic-mutant corpus names, cannot be edited without a declaration. (#32)
- **One artifact.** The package is built once, both Debian suites install those exact bytes, and the release publishes them with a provenance attestation and `RELEASE-EVIDENCE.json`. Every workflow action is pinned to a full commit SHA. (#33)
- **Debian dependencies, verified.** The package alone, on a base image of Debian 12 and 13, converges the demonstration Canon through its own service. (#35)
- **A security model.** [docs/security-model.md](https://github.com/kmosoti/Nomos/blob/v0.1.0-alpha.2/docs/security-model.md) names the assets, principals, and trust boundaries, and labels each claim established, assumed, or a non-goal. `SECURITY.md` says how to report a vulnerability. (#34)

## Upgrading From alpha.1

A state directory that is open to group or others is now refused, with an error that names it. The package makes `/var/lib/nomos` mode `0700`, so a packaged host needs nothing. A custom `--state` directory created by hand with a loose mode needs `chmod 700`.

## What It Does Not Establish

- **The repository rules.** Protected `main` and `v*` tags are repository settings that no code here can check.
- **Reproducible builds.** The package is built once so the bytes validated are the bytes published. Building it twice does not give the same bytes.
- **A signed package.** The package is not in an apt repository and carries no signature of its own. Verify it with `SHA256SUMS` and the attestation.
- **Hosts.** Every Debian result is from a privileged container booting systemd, not a virtual machine or bare metal.
- **Everything alpha.1 did not establish** still holds: power loss, other writers, scale, and real archives.

## Know Before You Use It

Everything in alpha.1's list still applies: the Canon is root and is not signed, there are no secrets, the journal grows, and removal undoes nothing. The security model says why, and what an operator should do.
