# Nomos 0.1.0-alpha.1

The first release: the masterless Cell on one Debian host. It reads a compiled Canon, observes the host, plans Actions for the Variances it finds, applies them, verifies the result, and records Events, on a timer, with no server. It is an alpha. Use it on hosts you can rebuild.

## Install

The package is for Debian 12 and 13 on amd64 with systemd. Download `nomos-cell_0.1.0-alpha.1_amd64.deb` and `SHA256SUMS` from this release, check the digest, and install:

```sh
sha256sum --check --ignore-missing SHA256SUMS
sudo apt-get install ./nomos-cell_0.1.0-alpha.1_amd64.deb
```

The [operator guide](https://github.com/kmosoti/Nomos/blob/v0.1.0-alpha.1/docs/operator-guide.md) takes a host from there to converged: author a Canon with the kit in `kit/canon`, trace it, enforce it, read the Events, and uninstall. Every claim it makes names the test that checks it.

## What It Does

- **Six resource families.** Files and directories with owner, group, and mode; systemd units, active or inactive, enabled or disabled, and refreshed when a file they depend on changes; kernel parameters; system and regular accounts; and Debian packages, at an exact version if one is named.
- **Five commands.** `trace` shows what `enforce` would do and changes nothing; `enforce` converges the host and ends `converged`, `indeterminate`, `non-convergent`, or `failed`, each with its own exit status; `events` prints the Event Log; `traits` prints what the Cell knows of the host; `import` adds a bundle's content to the Cell's store.
- **A service and a timer.** The package runs `enforce` two minutes after boot and fifteen minutes after each run ends, on the Canon at `/etc/nomos/canon.cbor`. Without a Canon, the service is skipped, not failed.
- **Unknown is not wrong.** A resource the Cell cannot read is Indeterminate, and nothing is planned for it.
- **Crash recovery.** The Cell journals every input to its kernel. A run that stops partway, killed or crashed, is recovered by the next: a refresh it owed is still owed, and it happens.

## What It Does Not Establish

- **Hosts.** Every Debian result is from a privileged container booting systemd, not a virtual machine or bare metal. No other distribution, and no architecture but amd64.
- **Power loss.** Recovery was tested with the Cell killed in its own process, not with the machine losing power mid-write.
- **Other writers.** The Cell assumes it is the only writer of what its Canon names. A foreign change is undone at the next run and reported only as the Action that undid it; two writers taking turns are not detected ([ADR 0008](https://github.com/kmosoti/Nomos/blob/v0.1.0-alpha.1/docs/adr/0008-ownership-and-identity.md)).
- **Real archives.** Packages were tested against a local repository of packages the tests built, not against Debian's archive.
- **Scale.** The demonstration Canon has seven Conditions. Canons of hundreds were not run on a host.

## Know Before You Use It

- **The Canon is root.** The Cell runs as root and does what `/etc/nomos/canon.cbor` says. Artifacts are not signed in this release: whoever can write `/etc/nomos` controls the host.
- **No secrets.** Cipher, the secret type, is not in this release. File content in the bundle and in the Cell's store under `/var/lib/nomos` is stored as plain bytes; do not put secrets in a Canon.
- **The journal grows.** It is never compacted in this release, and each run replays it whole. On the demonstration Canon, a converged run added 1,914 bytes and took 27 to 80 ms, so the timer's 96 runs a day add about 180 KB a day, and a run that changes something adds more. How long a year's journal takes to replay was not measured.
- **Kernel parameters last until boot.** The Cell sets them again at its first run after boot, two minutes in.
- **systemd's start limit applies to your units.** A unit the Canon restarts more than five times in ten seconds is refused by systemd, and its Action fails until the window passes; the next run retries. The Cell's own service has no such limit.
- **Removal undoes nothing.** `apt-get remove` and `purge` take away the Cell, not what it enforced. Your Canon in `/etc/nomos` stays.
- **The Canon build runs no code of its own.** A Canon crate may not depend on a procedural macro or have a build script; `cargo xtask check-canon-build` checks a crate's graph.
